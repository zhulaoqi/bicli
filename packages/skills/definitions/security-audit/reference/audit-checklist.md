# 安全审计检查清单

## 最小权限原则检查

| 角色 | 应有权限 | 不应有权限 |
|------|---------|-----------|
| viewer | `*:read` | 任何 `:write` |
| editor | `form:write`, `*:read` | `user:write`, `role:write`, `config:write` |
| admin | 全部 | — |

## 常见安全问题

### 1. admin 过多
- 建议：生产系统 admin ≤ 3 人
- 检查命令：`user_list` 按 roleId 筛选

### 2. 孤立角色
- 现象：角色存在但无用户使用
- 风险：可能被未来用户意外分配
- 建议：删除或记录为"待审批"

### 3. 过度授权
- 现象：editor 拥有 `role:write` 或 `user:write`
- 风险：可自行提权
- 建议：收回多余权限

### 4. inactive admin
- 现象：admin 用户状态为 inactive
- 风险：如果账号被重新激活，仍有最高权限
- 建议：停用前先降级为 viewer

### 5. 邮箱域名不一致
- 现象：部分用户使用非公司域名邮箱
- 风险：可能为外部人员或测试账号
- 建议：确认是否为合法用户

## 审计频率建议

| 审计项 | 建议频率 |
|--------|---------|
| 高权限用户审查 | 每周 |
| 角色权限审查 | 每月 |
| 用户分布审查 | 每月 |
| 全面安全审计 | 每季度 |

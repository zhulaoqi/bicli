# BiCLI Full-Page Chat 设计方案

> 目标：在现有右下角面板（`BiCLIPanel` 抽屉）基础上，提供一个**独立整页**的对话式 BI 工作台，支持完整的会话管理、模型切换、流式输出、斜杠命令、上下文引用、可视化渲染。
>
> 定位：面板 = 快捷问答（碎片化），整页 = 深度工作台（任务式）。两者共享会话、同步状态。

---

## 1. 业界做法速读（先学再做）

| 产品 | 值得抄的点 |
|------|-----------|
| **ChatGPT** | 左侧会话列表 / 顶部模型切换 / 新对话起手 Suggested Prompts / 消息悬停三件套（复制/编辑/重试） |
| **Claude.ai** | Artifact 侧栏独立滚动；代码块顶部工具条；引用附件 chip |
| **Cursor Chat** | 用 `@` 引用文件/符号作为上下文；Cmd+K 面板 vs Cmd+L 整页双模式；Diff 预览 |
| **Perplexity** | Sources 显式分离、Follow-up 建议按钮 |
| **Poe** | 单页多 Bot 切换，@Bot 内嵌切换 |
| **Dify / FastGPT** | 应用内调试面板：工具调用折叠面板、token 耗费统计 |
| **v0 / Lovable** | 整页布局：左历史 + 中对话 + 右预览（我们放 **图表/SQL 结果**） |
| **Notion AI** | Slash `/ 唤醒命令菜单`，上下文即插即用 |
| **Datadog Bits AI** | BI 场景里的最强参考：数据源/仪表盘作为 first-class 上下文 chip |

**核心抽象三件套**（后面设计都围绕这些展开）：
1. **Suggested Starters** — 新对话首屏 = 产品即说明书
2. **Slash `/` + At `@`** — 斜杠找动作，at 找上下文
3. **Streaming + Tool Timeline** — 输出边看边改边停

## 2. 交互总览 · 面板 vs 整页

```
┌──────────────────────────────────────────────────────────────┐
│ 场景 A（60% 使用）：右下角抽屉（已有的 BiCLIPanel）          │
│   - 宽 380px，高 70vh                                         │
│   - 适合"快速问一句、看一眼"                                  │
│   - 顶部有【全屏按钮】 ⤢  → 一键跳整页                        │
└──────────────────────────────────────────────────────────────┘
                       │ 点 ⤢ 或 Cmd+Shift+L
                       ▼
┌──────────────────────────────────────────────────────────────┐
│ 场景 B（40% 使用）：独立整页 /bicli                           │
│   - 新标签打开，路径 /bicli/chat/:sessionId?                  │
│   - 适合"多步复杂查询、沉浸阅读、反复迭代"                    │
│   - 抽屉与整页共享同一 sessionId → 状态实时同步               │
└──────────────────────────────────────────────────────────────┘
```

### 共享数据层

抽屉和整页是**同一个 React 应用的两种视图**，共用：

- **sessionId**（从后端 `/session/create` 拿，本地 `localStorage`）
- **消息流**（后端持久化，但前端订阅同一条）
- **选中的模型**（全局 Provider Context）

> 这样用户在抽屉里问了 3 句，点 ⤢ 进整页，上下文直接续着。

## 4. 用户能做什么 · 操作清单

### 4.1 斜杠命令 `/`（输入框开头打 `/` 唤起）

| 命令 | 作用 | 触发方式 |
|------|------|---------|
| `/help` | 显示所有命令和示例 | 任意时刻 |
| `/new` | 开新会话 | Cmd+Shift+N |
| `/clear` | 清空当前会话 | Cmd+K C |
| `/model` | 切换模型（弹出选择器） | Cmd+M |
| `/history` | 查看历史会话 | Cmd+H |
| `/save` | 把当前会话固定保存 | — |
| `/export` | 导出 Markdown / JSON | — |
| `/share` | 生成只读分享链接 | — |
| `/stop` | 中断当前流 | Esc |
| `/explain` | 让 AI 解释最后一步它做了啥 | — |
| `/retry` | 重跑上一条 | Cmd+R |
| `/settings` | 打开系统提示词、温度等设置 | Cmd+, |
| `/table <关键字>` | 快速搜表 | — |
| `/event <关键字>` | 快速搜事件 | — |
| `/sql <query>` | 直接把自然语言转 SQL，不走工具编排 | — |
| `/chart <type>` | 对最后一份结果换可视化（bar/line/pie） | — |

**实现要点**：命令菜单是本地数据驱动（不走 LLM），`fuzzy match` 实时筛选，方向键选择，`Tab/Enter` 确认。

### 4.2 At 引用 `@`（把对象塞进上下文）

| 前缀 | 选什么 | 结果 |
|------|-------|------|
| `@project:` | 项目 | 后续工具自动带 projectId |
| `@product:` | 产品 | 自动带 productId |
| `@event:` | 事件 | 把事件定义扔进 system |
| `@table:` | 数据表 | 把字段定义扔进 system |
| `@datasource:` | 数据源 | 指定 SQL 的 sourceId |
| `@file:` | 本地 CSV/SQL 文件 | 上传并引用（二期） |
| `@chart:<id>` | 已有的图表 ID | 让 AI 基于图表再加工 |

**UI 表现**：引用出现在输入框上方作为可关闭的 **chip**：

```
   [📁 Foo 项目 ✕]  [📊 dws_login_daily ✕]
   ┌─────────────────────────────────────┐
   │ 最近7天每天 DAU 变化                │
   └─────────────────────────────────────┘
```

### 4.3 快捷键（全局）

| 键 | 作用 |
|----|------|
| `Cmd+Shift+L` | 开 / 关整页 |
| `Cmd+L` | 聚焦输入框 |
| `Cmd+K` | 打开命令面板（所有 slash 命令的搜索入口） |
| `Cmd+Shift+N` | 新会话 |
| `Cmd+B` | 切换左侧栏 |
| `Cmd+J` | 切换右侧预览栏 |
| `Cmd+M` | 切换模型 |
| `Cmd+H` | 会话历史 |
| `Cmd+/` | 关键帮助 |
| `Esc` | 停止流 / 关弹窗 |
| `↑` / `↓` | 在命令菜单 / 历史输入间切换 |
| `Cmd+R` | 重跑上一条 |

### 4.4 消息操作（悬停出现）

- **复制**：纯文本 / Markdown / 代码块单独复制
- **重试**：用同样输入再问一次（可切模型）
- **编辑**：改用户消息后从该点重跑
- **引用**：把这条消息作为下一次提问的上下文
- **分叉**：基于此条另开分支会话
- **点赞/点踩**：反馈收集（后端打点）

## 5. 对话框上方的"显眼提示"设计

用户打开整页有三种状态，对应三种提示内容：

### 状态 1：空会话（Onboarding）

**大字问候 + 四张卡 + 三种进入方式**：

```
         👋 你好，我是 DataEye AI 助手

      帮你查数据、做分析、建表、写 SQL

   ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
   │ 📈 最近 │ │ 🔍 事件 │ │ 🗄 数据  │ │ 📝 自定 │
   │ 7天概览 │ │ 漏斗分析│ │ 表速查   │ │ 义 SQL  │
   └─────────┘ └─────────┘ └─────────┘ └─────────┘

   或
   [/ 浏览命令]   [@ 引用对象]   [🎓 教程]
```

卡片点击 = 预填一段示范 prompt，用户可改可发。

### 状态 2：有历史对话

输入框**正上方一条窄提示条**，显示 3 个**follow-up 建议**（由 AI 基于上一轮生成）：

```
   💡 可以继续问：
   [画成折线图] [对比上周同期] [按渠道拆分]
   ┌──────────────────────────┐
   │ 输入框                    │
   └──────────────────────────┘
```

这是从 Perplexity 学的。每次 LLM 回复完，让它顺便 suggest 3 个 follow-up（system prompt 里要求）。

### 状态 3：模型/权限/配额异常

顶部横幅 banner（可关）：

```
   ⚠️ 当前模型 qwen-plus 不支持图表渲染，建议切换到 qwen-max   [切换 ▸]
   ⚠️ 你的角色 analyst 无法执行 DDL，已自动降级为只读查询     [了解 ▸]
   ⚠️ 今日已用 87/100 次对话，明早 8 点重置                    [升级 ▸]
```

## 6. 流式输出设计

### 6.1 必须支持，协议选 SSE

后端 `POST /chat/stream` 用 SSE（`text/event-stream`），事件类型：

```
event: text_delta     data: {"content": "你好"}
event: tool_start     data: {"name": "dataeye_sql_query", "args": {...}}
event: tool_result    data: {"name": "...", "result": {...}, "duration": 120}
event: follow_ups     data: {"questions": ["画图", "对比", "拆分"]}
event: done           data: {"sessionId": "...", "messageId": "..."}
event: error          data: {"message": "..."}
```

为什么不选 WebSocket：单向推流 + 浏览器原生 `EventSource` / `fetch ReadableStream` 够用，简化得多。

### 6.2 前端渲染策略（关键体验）

- **字级流**：`text_delta` 来一个 token 就追加，带闪烁光标 `▋`
- **Markdown 懒解析**：每 100ms 或每 50 字符重解析一次，避免卡顿
- **代码块延后渲染**：等 ` ``` ` 闭合再高亮，进行时只显示纯文本
- **工具时间轴**：每个工具一行，状态 `⟳ running` → `✓ done (120ms)` / `✗ error`
- **图表/表格**：等 `done` 后再挂载（Echarts 不适合流式）
- **可中断**：`Esc` 或输入框 `⏹` 按钮调 `AbortController`，后端同时取消 LLM 调用

### 6.3 Token 速率视觉

右上角小徽章：`23 tok/s`（体感，类似 Claude 的流畅度指示）。

## 7. 模型切换设计

### 7.1 入口位置（三处，优先级从高到低）

1. **顶栏右上**：`模型: qwen-plus ▾` 下拉（**最常用**）
2. **输入框右下角**：发送按钮左边小胶囊 `qwen-plus ▾`（聚焦时不用跳顶部）
3. **斜杠 `/model`**：键盘党入口

### 7.2 下拉菜单内容

```
  当前:  qwen-plus   ●
  
  — 千问 —
  qwen-turbo     便宜快速       [免费]
  qwen-plus      推荐平衡       [✓ 已选]
  qwen-max       旗舰最强        [慢]
  
  — OpenAI —
  gpt-4o         视觉/多模态
  gpt-4o-mini    便宜
  
  — Anthropic —
  claude-sonnet  编码强
  
  — 自定义 —
  gpt-5.4 (aihub.x.x)
  
  ─────────────────────
  ⚙ 管理模型...      （打开模型管理页）
  ＋ 添加自定义...
```

**两个关键细节**：
- 每个模型右侧小标签（费用/速度/特点）
- 当前模型在工具响应能力不足时，下拉里相应 function-calling-only 场景项置灰 + tooltip

### 7.3 切换时机 + 副作用

| 场景 | 切换行为 |
|------|---------|
| 空会话 | 立即生效 |
| 已有消息 | 弹出确认："要在当前会话中切换吗？会丢失部分上下文兼容性" 选项：✅ 继续当前会话 ✅ 开新会话 ❌ 取消 |
| 流式进行中 | 按钮禁用 + tooltip "等待当前回复完成或 Esc 中断" |

### 7.4 存储

- **session 级**：每个 session 记住自己的 model（存后端 sessions 表）
- **全局默认**：存 `localStorage` → 新建 session 时带入
- **服务端配置白名单**：禁用某些付费模型（通过 `/chat/models` 接口返回用户可用清单）

## 8. 后端协议扩展（在现有 `/chat` 上加）

| 路径 | 方法 | 作用 |
|------|------|------|
| `POST /chat/stream` | POST | SSE 流式（替代现 `/chat`） |
| `GET  /chat/models` | GET | 列当前用户可用模型 |
| `POST /session/create` | POST | 创建会话 |
| `GET  /session/list` | GET | 会话列表（分组分页） |
| `GET  /session/:id` | GET | 会话详情 + 消息历史 |
| `DELETE /session/:id` | DELETE | 删会话 |
| `POST /session/:id/fork` | POST | 从某条消息分叉 |
| `POST /session/:id/export` | POST | 导出 Markdown/JSON |
| `POST /command/suggest` | POST | 根据当前上下文返回 follow-ups（可选，直接让 LLM 带回） |

> `/chat` 现有 API 保留作为兼容，`/chat/stream` 是新主力。

## 9. 前端技术选型（遵循 dataeye 栈：React 17 + antd 4）

| 能力 | 选型 | 理由 |
|------|------|------|
| 路由 | react-router-dom 5（已有） | 复用 |
| 状态 | Redux Toolkit / Zustand（局部） | 会话流用 Zustand 轻量，全局用 RTK |
| Markdown 渲染 | `react-markdown` + `rehype-highlight` | 主流选择，能流式 |
| 代码高亮 | `shiki`（VSCode 同款） or `prism-react-renderer` | Shiki 质量最高但体积大 |
| 图表 | ECharts for React（dataeye 已在用） | 直接复用项目现有封装 |
| SSE | 原生 `fetch` + `ReadableStream` | 支持 `AbortController`，比 `EventSource` 强（后者不能带自定义 header） |
| 命令面板 | `cmdk`（kbar 也可） | Vercel 做的，设计业界标杆 |
| 键盘快捷键 | `react-hotkeys-hook` | 轻量 |
| 动画 | `framer-motion`（按需引入） | 打字光标、抽屉 |
| 虚拟滚动 | `react-virtuoso` | 长会话性能 |

## 11. 权限和配额提示（上方横幅）

从用户视角必须清楚知道的状态（dataeye 的权限模型带过来）：

- **身份**：顶栏显示 `当前组织: Foo`，hover 出 `用户: admin@x.com, 角色: analyst`
- **权限边界**：如果用户问的东西超权限（比如 `DROP TABLE`），AI 会在顶部加条警告卡 `⚠️ 你的角色 analyst 无权执行此操作，已阻止`
- **配额**：状态栏展示 `今日消息 23/100`，满 80% 变橙，满 100% 变红并禁输入

## 12. 可视化渲染（右侧预览栏）

这是和普通聊天工具最大的差异化，**把结果放右边，不挤压对话**：

### 12.1 触发条件

AI 调完 `dataeye_sql_query` 且返回 `rows`，自动弹出右侧栏并选中"📊 图表"tab。

### 12.2 图表类型智能推断

| 数据特征 | 默认图表 |
|---------|---------|

## 16. 面板尺寸重设计（当前 420px 偏窄，实测不舒服）

### 16.1 问题拆解

现状 `Drawer width={420}` 的体感问题：

- 消息气泡最大宽度被挤到 ~340px，一句 30 字就换行 3 行，阅读累
- 工具调用的 tag + 参数字太多会把卡片挤变形
- SQL 代码块基本没法看（必横滚）
- follow-up 建议按钮一条放 3 个就挤了

### 16.2 尺寸方案（三档 + 拖拽）

**默认宽度 560px**（消息最大宽度约 480px，可以容纳中英文混排 2 行约 45 字，基本对标 ChatGPT 移动端宽度，也是 [Vercel AI Playground](https://sdk.vercel.ai) 的 chat 宽度）。

三档预设（顶栏右上小图标切换）：

| 档 | 宽度 | 场景 | 图标 |
|----|------|------|------|
| S 紧凑 | 420px | 瞄一眼，不挡业务页面 | ⊟ |
| **M 默认** | **560px** | 日常对话 | ⊡ |
| L 宽松 | 720px | 看 SQL / 表格 / 长回复 | ⊞ |
| F 半屏 | 50vw（最低 720） | 沉浸模式 | ◨ |

**自由拖拽**：在 Drawer 左边缘（紧贴业务页面那条线）放一个 `3px` 的抓手 `col-resize` 光标，按下拖动即可任意调节 `420 ≤ w ≤ min(1000, 80vw)`。

```
  业务页面 ←│→ AI 助手
           ↕   
      ░░░│░░░░░░░░░░░░░░░░
         ↑
      抓手（hover 变蓝 2px，active 变主题色 3px）
```

**记忆**：用户调过的宽度存 `localStorage.bicli_panel_width`，下次自动恢复。未调过时用档位默认值。

**移动端 / 窄屏兜底**：`window.innerWidth < 768` 自动变底部 sheet 模式（`placement="bottom"`，`height: 80vh`），不再右侧抽屉。

### 16.3 视觉微调（尺寸变大后）

- 消息气泡圆角 8 → 12，留白 12px → 16px
- 输入框 `autoSize` 上限 `maxRows: 4 → 6`
- 顶部 header 加入**尺寸切换按钮组**（三档）+ 原有**全屏按钮 ⤢**
- 整体背景从纯白改 `#fafbfc`（柔和对比），气泡白色，阅读更舒服

### 16.4 对业务页面的影响

- Drawer 是**浮层不挤压**（antd Drawer 默认 mask，但业务页不 resize），所以加宽不会导致业务页布局抖动
- 但需要：Drawer 打开时，**mask 半透明 0.2**（当前可能是 0.45 偏重），不要让用户觉得业务页不可交互
- 或者加一个 `mask={false}` 选项：允许用户**一边看业务页一边问 AI**（推荐给分析师用），顶部切换 `🔒 遮罩 / 🔓 无遮罩`

## 17. 浮动按钮可拖拽 · 完整交互设计

> 参考 iOS AssistiveTouch、Android Bubbles、抖音"播放器悬浮球"、企业微信小助手。

### 17.1 当前问题

```
┌─────────────────────────┐
│ 业务页面                │
│ （可能这里有表格/图表）│
│ xxxxxxxxxxxxxxxxxxxxxxx │
│ xxxxxxxxxxxxxxxxxxxxxxx │  ← 用户就想看这行
│ xxxxxxxxxxxxxxxxxxxxxxx │
│                    ┌──┐│
│                    │🤖││  ← 挡住了
│                    └──┘│
└─────────────────────────┘
```

### 17.2 核心交互原则

1. **点击 ≠ 拖动**：按下到抬起，**指针移动距离 < 5px** 视为点击（打开面板）；≥ 5px 视为拖动。
2. **X 轴贴边**：松手后**自动吸附到左右边缘**（AssistiveTouch 范式），不允许在屏幕中间悬浮。防止误触业务元素。
3. **Y 轴自由**：上下可随意放，但约束在**可视区域内**（离顶/底 ≥ 24px）。
4. **位置记忆**：拖完保存到 `localStorage.bicli_fab_pos = { edge: 'right', y: 300 }`。
5. **越拖越淡**：拖动中球体半透明 `opacity: 0.6`，松开复原。
6. **窗口 resize**：边缘对齐；Y 超出就按比例压回可视区域。

### 17.3 交互状态机

```
        idle
         │ mousedown
         ▼
      pressing  ───(移动 < 5px + mouseup)──▶  click ──▶ 打开面板
         │
         │ 移动 ≥ 5px
         ▼
      dragging ──(mousemove)──▶ 实时跟随指针（半透明）
         │
         │ mouseup
         ▼
      snapping ──(animate 200ms)──▶ 贴最近边缘 + 保存位置
         │
         ▼
        idle
```

### 17.4 视觉反馈

| 状态 | 视觉 |
|------|------|
| idle | 渐变紫色圆球 48×48，阴影 `0 4px 12px rgba(0,0,0,.15)` |
| hover | 放大 1.05，阴影加深 |
| pressing | 缩小 0.95（微反馈） |
| dragging | 半透明 0.6，光标 `grabbing`，阴影扩散 `0 8px 24px`，整球略放大 1.1 |
| snapping | 200ms `ease-out` 动画到贴边位置，带回弹 |
| unread | 右上红点 badge，拖动中仍保留 |

### 17.5 右键菜单（进阶）

右键浮球弹出小菜单：

```
  📍 固定在左侧
  📍 固定在右侧
  ───────────────
  📐 调整大小: S ⊡ M ⊞ L
  ───────────────
  🫥 暂时隐藏（按 Cmd+J 唤回）
  🚫 本次会话不再显示
```

**"暂时隐藏"**：最右贴边的角上留一个 4×40 的细条作为"唤回手柄"，鼠标悬停才出现完整球。这是 Youtube / B 站视频播放器右侧浮窗的玩法。

### 17.6 双击 / 长按

- **双击**：切换"点选模式"——把浮球变成十字准星，点击业务页面上任意元素（图表/表格/按钮），AI 助手自动把该元素作为上下文打开对话（需要业务组件配合埋 `data-bicli-context`）。这是 Cursor `Cmd+K` 选中代码的思路搬过来。**P3 阶段做**。
- **长按 500ms**：直接唤出右键菜单（移动端等价）。

### 17.7 避让区域（Safe Zone）

浮球拖动时识别以下"禁停区"，松开自动弹开：

- 顶部 Navbar：`y < 64`
- 底部操作栏：`y > innerHeight - 80`
- dataeye 左侧主菜单（如果它浮在右侧）：对应 x 区间
- 当前打开的弹窗：浮球 `z-index: 990`（低于 antd modal 1000），确保模态框能盖住它

### 17.8 和面板关系

- **面板打开时**，浮球**淡出隐藏**（`opacity 0 + pointer-events none`）。关闭面板再淡入。
- 否则浮球在面板右边缘外，点击位置会不明确。

### 17.9 响应式 / 移动端

| 屏幕 | 表现 |
|------|------|
| ≥ 1280px（桌面） | 浮球 48px，贴右 |
| 768 ~ 1280（平板） | 浮球 56px（稍大），贴右 |
| < 768（手机） | 浮球 → 固定在底部 tabbar 上方中间，不可拖（屏幕太小没必要） |

### 17.10 需要新增的依赖

- **无需第三方**，原生 `pointerdown/pointermove/pointerup` + `requestAnimationFrame` 即可。
- 动画用 CSS `transition` 或 `framer-motion`（如果已有）。
- 触控板手势 / 移动端支持 `pointer events` 统一即可。
